# Identify and respond to data risks with Microsoft Purview

Modern IT environments are becoming increasingly complex, and with that complexity comes new challenges in data protection. The shift to hybrid and remote work models, widespread use of cloud storage solutions, and the growing role of AI in workplace tools (such as Microsoft 365 Copilot) created an ecosystem where data is more fluid and accessible than ever before. As users collaborate across time zones and devices, the traditional concept of a “secure perimeter” no longer applies. Sensitive information now flows freely between managed and unmanaged devices, internal systems and external partners, and even across AI-generated content and automation tools.

These dynamics introduce new types of data risk, ranging from malicious insiders deliberately moving sensitive data from within the organization to external locations, to well-meaning employees accidentally sharing sensitive files through personal accounts or generative AI platforms. Traditional security controls, such as firewalls and static access policies, are no longer sufficient to address these evolving risks. Manual audits are time-consuming, reactive, and often too late to prevent actual damage. Organizations require modern tools that deliver real-time, contextual insights into how data is used, moved, and shared across cloud, endpoint, and user interaction layers.

Within the Microsoft 365 ecosystem, Microsoft Purview provides this functionality. It provides a unified platform for managing compliance, data protection, and insider risk. It includes powerful tools such as Insider Risk Management, Data Loss Prevention (DLP), Communication Compliance, and Activity Explorer. These tools work together to provide visibility and control across Microsoft 365 workloads, devices, and AI services like Copilot. With Purview, you can monitor for risks, define data protection policies, and take targeted action when necessary. Doing so protects your organization’s most valuable asset—its data.

### Identify governance risks in Microsoft 365 and Copilot

Governance risks emerge when sensitive information is accessed, shared, or used in ways that contradict company policy or regulatory obligations. Microsoft Purview enables you to detect these risks by analyzing signals across the Microsoft 365 environment, including apps like SharePoint, OneDrive, Teams, and even newer tools like Microsoft Copilot. The platform provides early indicators of risk through policy alerts, anomaly detection, and real-time telemetry.

These indicators allow admins to spot deviations from expected behavior, such as users attempting to export data, misuse of AI assistants, or unapproved data transfers. For instance, if your organization has a policy that prohibits highly confidential files from being shared externally, Purview can flag any violations, including violations initiated by AI tools. Since Purview surfaces these insights in a centralized dashboard, admins can quickly identify and respond to threats that might otherwise go unnoticed until a full-blown incident occurs.

This centralized dashboard is also useful for tracking behavior across AI integrations, such as Copilot. AI tools increase productivity, but they also create new vectors for data exposure. If Copilot inadvertently pulls information from sensitive sources while generating content, and that content is shared externally, it could constitute a data leak.

![Diagram showing tips on how to secure and govern data in Microsoft 365 Copilot and Microsoft Purview.](../../wwl/protect-govern-data-microsoft-365/media/copilot-and-purview.png)

Microsoft Purview includes the following tools to monitor and manage these interactions as part of your overall data governance strategy:

*   **Monitoring risk signals**. Microsoft Purview gathers and organizes data about potentially risky actions happening throughout the Microsoft 365 environment. It then provides admins with a comprehensive view of potential security and compliance issues within the Microsoft Purview portal. These risk signals might include policy violations, suspicious user behavior, and unauthorized data access or movement. For example, if users start uploading sensitive files to unmanaged storage like Dropbox or Google Drive and those uploads fail due to policy blocks, the portal logs these failed attempts. A sudden spike in such blocked actions might indicate users are either unaware of policy restrictions or attempting to bypass them deliberately. Monitoring these signals over time helps administrators detect early signs of misbehavior or misconfiguration before they result in data loss.
    
*   **Identifying potential data exfiltration attempts**. Data exfiltration refers to the unauthorized movement of sensitive data from within an organization to external locations. Purview surfaces these activities through behavioral analytics, such as detecting mass downloads from SharePoint or OneDrive, or transfers to personal USB drives. If a user downloads hundreds of documents labeled "Confidential" within a short timeframe, this behavior can be flagged as anomalous based on policy thresholds. These insights help security teams intervene early, potentially stopping insider threats or account compromises in progress. Whether intentional or accidental, such events are treated as high risk due to the volume and sensitivity of the data involved.
    
*   **Spotting policy violations by Copilot**. As part of the Microsoft 365 experience, Copilot interacts with user content to generate summaries, answer questions, or assist with document creation. If users prompt Copilot to access or summarize data labeled as “Highly Confidential,” it can inadvertently surface restricted content in unauthorized contexts. Microsoft Purview enables organizations to configure Data Loss Prevention (DLP) policies that restrict Copilot from processing or displaying certain labeled documents. If a user tries to use Copilot in a way that violates these policies, Purview logs the activity and can issue warnings or block the action entirely. This capability ensures that AI-enhanced productivity tools operate within established data governance boundaries.
    
*   **Detecting sudden spikes in sensitive data access**. Unusual spikes in access to sensitive data can be early indicators of account compromise or insider threats. Microsoft Purview continuously monitors baseline user behavior and flags deviations that exceed expected norms. For instance, if a user who typically accesses a handful of confidential files per week suddenly opens dozens in a single day, especially during nonworking hours or from an unfamiliar device, this behavior is highlighted for further review. These detections are enhanced when correlated with geographic location, device ID, and access type, enabling more nuanced analysis. Timely visibility into these spikes helps admins determine whether the activity is legitimate, mistaken, or malicious.
    

### Insider Risk Management

Insider threats are some of the most difficult to detect because they originate from users who already have legitimate access to your systems. Insider Risk Management in Microsoft Purview helps address this challenge by analyzing user activity in the context of defined thresholds, HR signals, and behavioral baselines. It works by combining machine learning, user activity data, and security signals to flag anomalies that could indicate potential misuse.

This feature doesn’t just look at what users are doing—it evaluates why the behavior might be suspicious. It considers factors like working hours, travel locations, role changes, and HR context (such as resignation notices or performance concerns). When properly configured, Insider Risk Management provides a nuanced, context-aware system for identifying and responding to potential internal threats.

Admins can create policies that focus on specific scenarios, such as high-volume file transfers, access to sensitive data during unusual hours, or sending confidential documents to personal email accounts. Alerts are surfaced in a dashboard that enables reviewers to view activity logs, assess severity, and take appropriate actions, such as notifying HR, restricting access, or launching a full investigation.

*   **Detecting mass file downloads**. Mass downloads of sensitive files can signal preparatory steps for data theft or accidental mismanagement by users. Insider Risk Management in Purview lets admins define policies that watch for such behavior, such as downloading more than 50 files marked as "Confidential" in 24 hours. When the system detects this threshold has been exceeded, it automatically generates an alert and logs the event, including the file names, locations, and user information. Admins can then review these actions in context—whether they occurred during an offboarding process, a role change, or were simply misuse of access. These rules are especially valuable for identifying risky behavior before it escalates to actual data loss.
    
*   **Flagging data shared to personal email**. Sharing internal documents to personal or external email accounts often violates corporate policy, as it bypasses formal controls and data residency requirements. Microsoft Purview detects when sensitive content is sent to domains like gmail.com, yahoo.com, or other unmanaged addresses. When the system detects this type of activity, it flags the incident and can automatically notify the user, block the message, or escalate to compliance teams. This response is particularly useful when combined with DLP and Information Protection labels, which provide classification context for the shared content. Admins can then investigate further, determine intent, and take corrective action as needed.
    
*   **Identifying abnormal behavior involving working hours or travel context**. Abnormal access patterns—such as sign-ins at 3 a.m. or from IP addresses outside the employee’s usual location—can be signs of suspicious behavior. Purview begins by using behavioral baselining to understand what’s “normal” for a user in terms of access time, location, and data volume. When a deviation is detected, such as someone accessing files during leave or while allegedly out of the country/region, Purview flags the event for follow-up. These anomalies become more meaningful when combined with HR data, such as approved travel or leave schedules, allowing for more targeted reviews and fewer false positives.
    
*   **Applying thresholds and HR integrations**. Purview becomes even more powerful when you integrate it with HR systems to bring in contextual signals, such as employee resignation notices, role changes, or disciplinary actions. You can set behavioral thresholds—like large data transfers or unusual downloads—and have them act as triggers when HR signals are also present. For example, if an employee submits a resignation and is suddenly exporting customer lists to a personal device, the combination of those two signals elevates the risk score and justifies further investigation. These proactive policies help organizations monitor for insider threats during high-risk transition periods like terminations or team transfers.
    

### Data loss prevention (DLP)

DLP is one of the most foundational tools in Microsoft Purview for enforcing data security policies. It uses policies that enable organizations to detect, block, or audit the movement of sensitive data based on content inspection and contextual rules. These policies apply to a wide range of activities, such as copying data to USB drives, emailing documents, uploading to cloud storage, or interacting with AI tools like Copilot.

Microsoft Purview DLP policies use classification rules, sensitivity labels, and pattern matching to inspect data. This process includes built-in sensitive information types such as credit card numbers, Social Security numbers, or government-regulated data. Admins can also create custom patterns using regular expressions or dictionaries. Policies are enforced in Microsoft 365 apps (like Outlook, Teams, SharePoint), on devices (through Defender for Endpoint), and through session controls in Microsoft Defender for Cloud Apps.

A key benefit of Purview DLP is that it supports flexible actions. You can allow actions with user justification, block them entirely, or allow and log for review. Doing so ensures that security doesn’t come at the cost of business productivity. DLP also integrates deeply with alerts, incident management, and audit logs, so admins can respond quickly when risky behavior is detected. Microsoft Purview DLP incorporates the following tools:

*   **DLP policies**. Microsoft Purview DLP policies enable you to take precise actions when sensitive data is handled in potentially risky ways. For example, you can configure a policy to block uploading of “Confidential” documents to non-Microsoft cloud services like Dropbox or Google Drive. Alternatively, users might be permitted to proceed after providing a business justification—such as “vendor collaboration”—which is then logged for audit purposes. This just-in-time decision-making enables organizations to protect sensitive data while giving employees a way to justify legitimate needs without being unnecessarily blocked. All actions and exceptions are recorded to ensure compliance visibility.
    
*   **Device-level enforcement in Defender for Endpoint**. Purview DLP integrates with Microsoft Defender for Endpoint to enforce policies at the device level, offering protection even outside the cloud. Onboarded devices running Windows 10+, Windows 11, or supported versions of macOS can block or log local actions such as copying files to USB drives, printing sensitive documents, or using clipboard tools to move data into unmanaged applications. For instance, if a user tries to paste content from a confidential report into an unauthorized web form, the system can block the paste and log the attempt. This device-level control is critical for hybrid and remote environments where traditional network controls are ineffective.
    
*   **Alerts trigger automated or manual investigations**. When a DLP rule is triggered, such as an attempt to email a sensitive spreadsheet externally, Purview generates an alert with full details: who triggered it, when, where, what data was involved, and which rule was violated. These alerts appear in the Microsoft Purview portal and can also be routed to Microsoft Defender XDR, Microsoft Sentinel, or other Security Information and Event Management (SIEM) tools. Depending on the severity, alerts can trigger automated workflows through Logic Apps or Power Automate, or be handled manually by compliance staff. This flexible response framework enables organizations to scale their incident handling based on volume and risk level.

### Communication Compliance

Communication Compliance in Microsoft Purview helps you monitor user communications—such as emails, Teams messages, Yammer posts, and even Copilot chat prompts—for content that violates corporate policies or regulatory requirements. This feature is particularly useful for detecting harassment, abusive language, insider trading, data leaks, and other types of inappropriate or risky communication behavior.

Purview uses a combination of pattern-based detection (like regular expressions for keywords) and machine learning classifiers that are trained on real-world examples. These models can detect context-sensitive violations, such as discussions that resemble market manipulation or sharing of sensitive terms in inappropriate settings. Communication policies are customizable by user group, communication channel, keyword, language, and more.

The review process involves a dedicated dashboard for compliance analysts. They can assess flagged messages, tag false positives, escalate high-severity messages, or notify HR or legal teams. For organizations in regulated industries like financial services or healthcare, Communication Compliance provides a critical layer of oversight that helps meet audit and legal discovery obligations.

*   **Using pattern‑based and machine learning classifiers**. Communication Compliance in Microsoft Purview uses both traditional pattern matching (such as regex and keyword dictionaries) and machine learning classifiers to detect inappropriate or risky content in messages. This type of content often includes signs of harassment, regulatory violations, and insider trading conversations. For instance, a classifier might flag an email chain where an employee discusses “delaying the announcement until after earnings,” which could be interpreted as an attempt to manipulate market timing. The combination of structured patterns and adaptive classifiers allows for broader and more accurate detection.
    
*   **Reviewer dashboard**. All flagged messages are presented in the Communication Compliance reviewer dashboard, where authorized analysts can see message details, including sender, recipients, content snippets, and policy matches. From here, reviewers can dismiss the event, send user notifications, escalate to HR or legal, or tag it for future policy training. For example, if a message contains borderline language but no policy breach, the reviewer might provide feedback to the user without formal action. This human-in-the-loop process allows for context-aware decisions and supports policy tuning.
    
*   **Industry‑specific custom policies**. Organizations can configure Communication Compliance to align with industry regulations, such as FINRA for financial services or HIPAA for healthcare. Custom policies might focus on detecting “material nonpublic information” (MNPI), drug-related language, or prohibited political statements depending on the industry’s regulatory framework. These policies can also include thresholds for risk scores or match confidence, ensuring that only high-confidence events are escalated. Over time, organizations can fine tune these policies to help reduce alert fatigue and improve enforcement accuracy.
    

### Activity Explorer

Activity Explorer in Microsoft Purview is a centralized investigation and visualization tool. It helps compliance and security analysts understand user actions and correlate them with policy matches, risk events, or data sensitivity classifications. It acts like a forensic timeline of what users did with sensitive data across emails, file shares, downloads, labeling, policy violations, and more. Rather than jumping between multiple logs or dashboards, Activity Explorer provides a consolidated view of user behavior. This design makes it easier to investigate incidents or identify risky patterns.

Unlike alert-focused dashboards, which only surface predefined risks, Activity Explorer gives you full visibility into user and data activity, even when it doesn’t trigger a policy violation. Doing so enables more proactive exploration, such as identifying unusual data movement before it escalates into an incident. Whether you're trying to determine the root cause of a DLP alert, investigate insider behavior, or audit data flows, Activity Explorer serves as your starting point.

The Activity Explorer interface is highly interactive. You can filter events by date, user, file name, sensitivity label, activity type (for example, “Shared externally” or “Labeled as Confidential”), or specific policy matches. You can also view the activity as a chronological timeline, helping you connect sequences of behavior that might otherwise seem unrelated. For example, a document being labeled, then downloaded, then emailed externally, all within minutes.

*   **Dashboard for sensitivity labels, sharing, and DLP matches**. Activity Explorer provides a consolidated view of user activity across Microsoft 365, enabling admins to see how users are interacting with labeled content, sharing files, and triggering DLP policies. Events are visualized chronologically with metadata such as file names, users, activity types, and device details. For instance, you could quickly identify that a user labeled a file as “Highly Confidential” and then shared it externally, allowing you to correlate the sequence with policy enforcement and potential data loss.
    
*   **Filtering by user, policy, date, or file type**. The tool offers powerful filters so investigators can drill into specific activity types, such as “external file shares by user X in the last seven days.” It can also search by file type, policy ID, or classification label. These filters are essential when triaging alerts or following up on an insider risk signal. Rather than reviewing all logs, admins can isolate the relevant subset of actions and examine them in detail, making the investigation process more efficient and targeted.
    
*   **Drill‑down into sequences and timelines**. Activity Explorer organizes actions into linked timelines, showing visual sequences like: document labeled, then downloaded to USB, then emailed externally. This visual linkage helps analysts understand user intent and the path data took through the organization. Each event includes deep context—timestamp, user identity, device info, label history, and risk scores—so investigators can reconstruct incidents accurately. These timelines are critical in incident response, helping teams determine whether an action was deliberate, accidental, or indicative of compromised credentials.
